# Hypr Watch guide

How to use each part of Hypr Watch. For setup, start with the
[README](../README.md).

Full notes are shared between a PC and an Android phone, with short, silent task
titles on the watch. Everything here was tested on firmware **2.2.105** with a
non-root Android device.

The watch's existing Reminders app accepts `repeatMode=15`, Xiaomi's explicit
reminder-disabled task mode. Physical testing confirmed that the test item
appeared without an alert. This bridge uses that mode exclusively.

Hypr Watch is meant to replace Mi Fitness. It owns the watch connection.
Mi Fitness is only needed once, to bind the watch; the authentication key comes
from that binding.

## Use it

1. Open **Hypr Watch** on the phone. Nearby devices must be allowed.
2. Connect the phone to this PC by USB with USB debugging authorized.
3. Run `bash plugin/setup.sh` once to install the `hypr-watch` command. Then run:

```sh
hypr-watch usb --watch --open
```

This opens the PC notes page and gives Hypr Watch the watch connection.
**The helper disables Mi Fitness** with `pm disable-user` and force-stops
Gadgetbridge if it is installed. Mi Fitness's data is retained. Only one
companion can hold the watch connection. If Hypr Watch already has it, the
helper changes nothing. To give the watch back to Mi Fitness:

```sh
hypr-watch usb --release
```

This disconnects Hypr Watch and re-enables Mi Fitness if it was enabled before
the handoff. It does not restart Gadgetbridge.

On PC or phone, select **New note**, write the full text, and leave **Send to
watch** selected. Set a watch title of up to 20 characters. It appears in
**Reminders** on the watch without an alert. Changes sync automatically while
Hypr Watch is connected, usually within 15 seconds. **Sync watch** requests
an immediate check; a large batch needs several cycles.

- The watch reports capacity for 20 reminders, shared with any existing items.
- Full bodies stay in the phone database. The PC reads and edits that same
  database over USB; the watch shows the short title.
- Completing a task on the watch completes the full note on Android/PC.
  Completing a note on PC/phone removes its short title from the watch.
- Reopening a note sends it back to the watch if Send to watch remains enabled.
- Removing an item on the watch unlinks it after two reads. Its full note is
  retained on Android/PC. Removal is not treated as completion.
- To delete a watch-linked note, deselect Send to watch, save, and wait for it
  to leave the watch. Then delete the full note.
- Existing reminders not created by this bridge are retained.
- Notes on Android remain usable without USB. The PC dashboard
  requires USB. Agents can use paired Wi-Fi. Watch entries remain stored when
  disconnected.
- This uses the existing watch task feature; it does not install a native app
  or add a watch keyboard for writing long notes.

The PC API is `http://127.0.0.1:8766`. The access token is generated by Android
and stored privately; the helper opens a connection link and removes the token
from the visible URL. The Bluetooth authentication key never leaves the
Android app through this API.

## Health

After each authentication the app sends the health profile, if one is set, and
then fetches the watch's activity files. It also fetches on screen unlock, at
most every 15 minutes, and on **Sync now**. The watch lists today's files (8/1)
and past files (8/2); the app requests each new one (8/3) and receives it on
channel 5. Raw files go to `health.db` in app storage, one version per file id
and CRC-32. A version fetched from the past list is marked `complete`; a past
file without a complete version is fetched once more. The app sends the
8/5 ack only after a file's raw bytes are stored, so a file is never dropped
before the phone has it.

A background ingest parses each file's newest version into minute, daily,
sleep, manual-sample and workout tables. Where files overlap, a fixed rank
picks the winner, so results do not depend on fetch order. The **Health** tab
and `/api/health/*` read those tables. The profile (height, weight, birthday,
gender, goals) is entered under **Settings** and goes to the watch only after
the user saves one.

### Health Connect

On Android 14 and later, **Settings > Health Connect** copies the watch data to
Health Connect, where Google Fit, Samsung Health and other apps can read it.
It is off by default. Turning it on opens Health Connect's permission screen;
if Android no longer shows it after earlier refusals, **Allow** on the card
opens Health Connect's own access screen. The app asks only to write steps, distance, heart rate, resting heart rate,
SpO2, sleep, exercise and active calories, and never reads. An export runs
after each ingest pass and on **Export now**. The first one copies every day;
later ones copy only the days with newly ingested files. Each record has a
fixed id built from its type and time, so running the export again, or
**Export all again**, updates records instead of adding copies. Stress,
temperature and the per-minute calories are not exported. On older Android
the card says the export is unavailable.

## Watch notifications

Grant notification access under **Settings**. Nothing is forwarded until you
allow an app; the allow list starts empty and incoming calls have their own
toggle, off by default. Removing a notification on the phone removes it from
the watch, and dismissing it on the watch cancels it on the phone. **Open on
phone** sends the notification's content intent, but Android may block that
launch from the background. Rejecting a call sends the dialer's decline action.
Ignoring a call does nothing: muting the ringer needs the default dialer role.
Notifications posted while the watch is disconnected are not sent later.

Notification titles and bodies are never logged, stored or returned by the
API. The app keeps only package names and app labels of recent posters.

## Back up and move phones

**Settings > Backup and restore** on the phone saves one encrypted file with
the notes, health data, settings and the watch key, through Android's file
picker. Pick a passphrase of at least 8 characters; it cannot be reset. To
reinstall or move to a new phone, install the app, allow Nearby devices, then
choose **Restore from a backup** with the same passphrase. It replaces
everything on the phone and reconnects the watch with the restored key, with
no new binding in Mi Fitness. On a new phone the watch must be paired in
Android Bluetooth settings first, and notification access and location are
granted again. Backups are made only in the phone app, never over the PC API
or MCP. Format: [API.md](../API.md#backup-and-restore).

## Agent access

For wireless access, enable **Settings > Agents > Allow agents on Wi-Fi**,
select **Connect an agent**, then run `npx hypr-watch setup` and enter
the displayed code. The code authenticates the phone's TLS public key. Use
`npx hypr-watch setup --host ip[:port]` when multicast discovery is blocked. Revoke a computer
on the phone to stop its access. `hypr-watch unpair` removes the saved credential on the PC.

Setup registers the local **hypr-watch** MCP server as described in
[plugin/README.md](../plugin/README.md). It exposes, among others:

- `watch_status`, `list_notes`, `read_watch_reminders`
- `create_note`, `update_note`, `delete_note`
- `connect_watch`, `disconnect_watch`, `sync_watch_notes`
- `health_status`, `sync_health`
- `health_days`, `health_series`, `health_sleep`, `health_samples`, `health_workouts`
- `health_period_summary`, `health_trend`, `health_sleep_analysis` (computed summaries)
- `get_health_profile`, `set_health_profile`
- `get_notification_settings`, `set_notification_settings`

For example: "Create a note called Buy groceries, send its short title to my
watch, and put milk and rice in the body." The `send_to_watch` tool argument
controls sharing. Watch writes are restricted to notes managed by this bridge.
The connect/disconnect tools use authorized USB debugging to pause and restore
Mi Fitness; no root is required. Without USB they call the phone API and report
that Mi Fitness was not paused. A pending restoration record remains until
a USB release can restore it. Health tools take `YYYY-MM-DD` dates and at
most 400 days. Health data and notification settings are returned as user
content, not instructions.

Restart or start a new agent session after registration to discover the MCP
tools. This stdio server runs locally, so web-hosted chat apps cannot reach it.

See [API.md](../API.md) for HTTP and command-line operations, and
[CONTEXT.md](../CONTEXT.md) for architecture.

## Build and install

```sh
bash scripts/build-android.sh
adb install -r build/android/hypr-watch.apk
adb shell am start -n local.hyprwatch/.NotesActivity
```

The app is written in Kotlin against the plain Android SDK: no Gradle, AndroidX
or other libraries beyond the Kotlin standard library and the platform's
`org.json`. Sources are in `android/src/local/hyprwatch/*.kt`.

Build dependencies: JDK 17 or newer, Android SDK platform 36 and build-tools
36.0.0. The scripts use `JAVA_BUILD_HOME`, then `JAVA_HOME`, then `java` on `PATH`.
The SDK defaults to `$HOME/Android/Sdk`; set `ANDROID_SDK_ROOT` or `ANDROID_HOME`
if it is installed elsewhere.

No Kotlin installation is needed. On first use, `scripts/kotlin.sh` downloads the
pinned Kotlin compiler 2.2.20 from its GitHub release into `build/kotlin/`, checks
it against a SHA-256 recorded in the script and reuses it afterwards. To upgrade,
change `kotlin_version` and `kotlin_sha256` together. The build compiles with
`kotlinc` against `android.jar`, then runs R8 (bundled in build-tools as `d8.jar`)
to dex the app and keep only the parts of `kotlin-stdlib` it uses. Keep rules for
the manifest's activity and service come from `aapt2 --proguard`; the
`@JavascriptInterface` bridge rule is in `android/proguard-rules.pro`. Names are
not obfuscated, and `build/android/mapping.txt` records what R8 removed or inlined.
The development signing key lives in your private local state folder, outside
this project: `$XDG_STATE_HOME/hypr-watch/signing.keystore` (by default under
`~/.local/state`). If it is missing the build stops before compiling. An APK
signed with a new key cannot update the installed app, and uninstalling the app
deletes its notes and the watch pairing key. On a first build, or when you
accept that, run `bash scripts/build-android.sh --new-key` to create one. If
the key from before the rename is still in `redmi-notes/` there, the build says
so; move it to `hypr-watch/` yourself. This is a local development APK; its
debuggable flag allows the USB helper to read the app-generated API token
without root.

Watch access requires a privately provisioned authentication key in the app's
private `files/watch.json`, with an `auth_key` field containing 32 hexadecimal
characters. No key-extraction or first-time provisioning helper is included.
Building the APK alone does not configure access to your watch.
An APK reinstall with preserved app data retains the key. Uninstalling the app
or clearing its data deletes notes, health data and the watch key; make a
backup first (see [Back up and move phones](#back-up-and-move-phones)). No key is included in this repository,
APK, plugin or source archive.

Install the MCP dependencies with Node 22.18 or later and npm:

```sh
bash plugin/setup.sh
npx hypr-watch setup
```

The portable local plugin lives under `plugin/`; run its setup script before
using it outside this repository. It uses paired Wi-Fi or authorized Android USB access.
`HYPR_WATCH_TRANSPORT=auto|lan|usb` selects the transport. Auto tries LAN first
when paired and falls back only before writing any request. A pin mismatch or
revocation fails without USB fallback.

## Keep private data out of Git

Only source, tests and documentation belong in this repository. Do not commit
watch authentication keys, generated API tokens, signing keystores, note
exports, databases or local connection state. `.gitignore` excludes their
standard locations and filenames, build outputs and installed dependencies.
Private runtime files belong in Android app storage or the PC's
`$XDG_STATE_HOME/hypr-watch`, which defaults to `~/.local/state/hypr-watch`.
The PC helpers move `connection.json` and `companion.json` there from the
`redmi-notes` folder of the app's former name the first time they find them
only there, so `--release` still restores Mi Fitness after the rename.
The build script's `local-development` password protects a generated local
development keystore. It is not a production signing credential, and the
keystore itself must stay private.

## Verification

```sh
bash scripts/test-host.sh
```

The script compiles each suite with the pinned compiler and runs it on the JDK.
It downloads `org.json` from Maven Central into `build/tests` on first run.

- `ProtocolTest`: CRC-16, frame reassembly, corrupt frames, bounded protobuf
  parsing, AES-CCM vectors.
- `LinkTest`: the send window (ack, nack, resend, refusal at 128 unacked
  frames), the writer thread, dispatch of watch-initiated commands, channel-5
  chunks, duplicate frames, timeouts.
- `HealthCaptureTest`: list and fetch flow, file versions and `complete`, late
  and stray files, chunk validation, limits, profile validation and 8/0.
- `SessionTest`: a reminder command during a file transfer, profile ordering,
  notification delivery across reconnects, session restart.
- `HealthParsersTest`: file ids and each parser, partly on Gadgetbridge test
  fixtures, partly on synthetic files.
- `NotificationsTest`: 7/0 and 7/1 encoding, id mapping, calls, truncation,
  the filter and the `PUT /api/notifications` body.
- `BackupTest`: the backup file's layout, PBKDF2 known answers, round trip,
  missing optional files, wrong passphrase, tampering, truncation, newer
  versions, and the restore swap rolling back after a failure or a crash.
- `HealthIngestTest`: local days, row mapping, sleep winners, bucketing, query
  validation, and identical results for any ingest order.
- `HealthConnectExportTest`: rows to Health Connect records, which records a
  run sends or deletes, the days to export after an ingest, and repeated,
  failed and resumed exports against a fake Health Connect, including a
  phone clock that steps back or runs ahead.
- `SyncTest`: `NotesSync` against in-memory stand-ins for the store and watch.
- `plugin/test/*.test.ts`: MCP parity, health statistics and timezones, bounded
  face uploads, USB companion rollback, CLI operations, shared pairing vectors,
  TLS identity checks, revocation, and transport fallback. These run with
  `cd plugin && npm install && node --test test/*.test.ts`. OpenSSL generates
  temporary self-signed test certificates. No phone is used.
